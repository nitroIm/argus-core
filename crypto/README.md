═══════════════════════════════════════════
1. МИССИЯ
═══════════════════════════════════════════

Собирать качественные рыночные данные BTC/ETH
для поиска закономерностей и предсказания
движения цены.

Принципы:
1. Качество данных важнее скорости
2. Данные не теряются никогда
   (fallback + backfill + cross-check + backup)
3. Один донор даёт 95% (не смешивать)
4. Дубликаты исключены PRIMARY KEY
5. Битые данные → карантин, не в БД

8. PATTERNS — 0/1 + MARKOV + N-GRAM
═══════════════════════════════════════════

Бинарный график:
  1 = close > open (рост)
  0 = падение

Markov:
  P(1|1)  продолжение роста
  P(0|1)  разворот вниз
  P(1|0)  отскок вверх
  P(0|0)  продолжение падения

Чтение:
  P(1|0) > 0.58 → mean reversion
  P(1|0) < 0.42 → momentum

N-граммы:
  окна типа 1111, 1011, 0011
  смотрим что идёт СЛЕДУЮЩИМ

Первые наблюдения (101 свеча):
  BTC: 1111 → ↑ 64% (N=14)
  ETH: 1111 → ↑ 67% (N=12)
  BTC: P(1|0)=0.60 → отскок
  ETH: P(1|0)=0.56

⚠️ N маленькие. Через месяц N=100+.

Таблица: price_patterns

12. CORRELATE — ПРАВИЛА
═══════════════════════════════════════════

Ищет правила «если X → Y».

Типы:
  простые:  funding < -0.005% → UP
  двойные:  OI > +2% AND LS > 1.5 → UP
  тройные:  funding<0 AND LS<1.0 AND OI↓

Порог: ≥ 3 сэмпла, confidence ≥ 55%.

Первые наблюдения:
  BTC: OI > +2%      → UP 80% (N=5)
  BTC: funding >0.005 → UP 67% (N=12)
  ETH: funding >0.005 → UP 60% (N=5)

⚠️ Это наблюдения. Ждём N=50+.

18. КАЧЕСТВО ДАННЫХ — 10 ПРАВИЛ
═══════════════════════════════════════════

1. Идемпотентность
   PRIMARY KEY:
     candles: (symbol, timeframe, timestamp)
     funding: (symbol, timestamp)
   ON CONFLICT DO NOTHING

2. Валидация перед записью:
   JSON? ключи? цены > 0?
   изменение < 30% за час?
   timestamp свежий (< 2ч)?
   timestamp в UTC?
   Не прошло → rejected_data

3. Fallback по метрике
   (не по бирже!)

4. Cross-check между источниками
   расхождение > 0.5% → anomaly_log

5. Backfill раз в сутки (03:00)
   проверка целостности за 24ч

6. Retention 90 дней
   удаление только из raw_*
   агрегаты — НАВСЕГДА

7. Бэкап CSV раз в неделю
   (в отдельный репо)

8. Immutable append-only
   только INSERT, никаких UPDATE

9. Колонка source в каждой таблице
   для аудита

10. Журнал collect_log
    каждый прогон: что, сколько,
    откуда, статус, ошибки

19. КРИТИЧНЫЕ ПРАВИЛА
═══════════════════════════════════════════

1. НЕ удалять таблицы Supabase
2. НЕ менять PRIMARY KEY
3. Смена донора — через priority.py,
   не хардкод
4. Retention сырья 90 дней
5. Только INSERT, никаких UPDATE
6. Все времена UTC (TIMESTAMPTZ)
7. Секреты — только GitHub Secrets
8. Бот — на VPS, не в Actions
9. crypto/data/*.json — оперативные
   (runner.py передаёт между этапами)
10. Crypto enrich/collect workflow
    должны иметь contents: write
    (иначе JSON не коммитятся)
11. Каждый workflow — один процесс
    (через runner.py)
12. Строки в коде ≤ 55 символов
13. Логи на английском

21. ЧАСТЫЕ ПРОБЛЕМЫ
═══════════════════════════════════════════

Симптом                  → Причина → Фикс
-------------------------|-----------------|------
Pipeline 8+ минут        → limit=720     → --mode=incremental
Network is unreachable   → IPv6 Direct   → Session Pooler
CoinGecko 429            → rate limit    → кэш 10 мин
multiple primary keys    → схема         → один PK
Данные не появляются     → cron молчит   → запустить вручную
Ложный "успех"           → INSERT без    → проверять added
                           rowcount
JSON не коммитится       → нет contents: → добавить write
                           write
Утренний отчёт пустой    → enrich не     → contents: write
                           коммитит
Строки рвутся на телеф.  → > 55 символов → писать короче
