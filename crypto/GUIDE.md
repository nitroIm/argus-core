### 🎯 Миссия модуля

Собирать качественные рыночные данные BTC и ETH для последующего анализа,
поиска закономерностей и предсказания движения цены.

**Принципы:**
1. Качество данных важнее скорости
2. Данные не теряются никогда (fallback + backfill + cross-check + бэкап)
3. Не смешивать источники без причины — один донор даёт 95%
4. Дубликаты исключены через PRIMARY KEY
5. Битые данные → карантин, не в основную таблицу

### ⚙️ КАК РАБОТАЕТ СБОР

**Каждый час (cron):**
1. Для каждой метрики → fallback-цепочка бирж
2. Первая успешная → валидация → INSERT с `ON CONFLICT DO NOTHING`
3. Битые данные → `rejected_data`
4. Сводка → `collect_log`
5. Cross-check: OKX vs CoinGecko → детект аномалий

**Инкрементальный режим (по умолчанию):**
- 3 записи за раз (для каждой метрики)
- Время: 4 минуты
- Используется в cron

**Backfill режим (вручную):**
- 100-720 записей за раз
- Восстановление истории
- `python crypto/collect/pipeline.py --mode=backfill`

### 🔑 КЛЮЧЕВЫЕ РЕШЕНИЯ

1. **OKX как донор** — работает из GitHub, отдаёт всё, данные качественные

6. **Cross-check** — расхождение цен = сигнал манипуляции
7. **Не пишем в git** — все данные в Supabase, репо не пухнет
8. **Bot на VPS** — отделён от логики, работает 24/7

### 🚨 ЧАСТЫЕ ПРОБЛЕМЫ

| Симптом | Причина | Решение |
|---|---|---|
| Pipeline идёт 8+ минут | limit=720 (не инкремент) | Проверить `--mode=incremental` в workflow |
| `Network is unreachable` | Direct connection (IPv6) | Использовать Session Pooler |
| CoinGecko 429 | Rate limit | Кэш на 10 мин (уже) |
| `multiple primary keys` | Ошибка в схеме | `causal_links` — один PRIMARY KEY |
| Данные не появляются | cron не сработал | Запустить вручную |
| Ложный «успех» | INSERT без rowcount | Проверять `added` в логе |
